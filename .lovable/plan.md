# Плант по переработке логики квиза

Полная переработка структуры и логики квиза на динамическую систему ветвления. Каждый вопрос будет зависеть от предыдущих ответов, обеспечивая релевантность рекомендаций.

## Изменения

### Конфигурация квиза (`src/config/quiz.ts`)
- Полностью обновить `QUIZ_CONFIG.steps`, внедрив 6 независимых веток:
    - **Глубокое расслабление (relax)**: вопрос про зоны расслабления -> формат воздействия.
    - **Спина, шея и плечи (back_neck)**: множественный выбор зон напряжения -> желаемый результат.
    - **Лёгкость и отёчность (lightness)**: зоны тяжести. Изоляция ветки "Лицо", если выбрано только оно.
    - **Лицо (face)**: цели ухода -> формат процедур. Полная изоляция от услуг для тела.
    - **Оздоровительные практики (wellness)**: выбор практики -> необходимость массажа.
    - **Не знаю (unsure)**: уточнение направления. Если все еще неясно — рекомендация векторного массажа как основного для первого визита.
- Добавить строгие `showIf` условия на основе ID ответов (а не текста).
- Обновить список услуг (`services`) и сценариев (`scenarios`) для соответствия новым требованиям.

### Компонент модального окна (`src/components/quiz/QuizModal.tsx`)
- Реализовать динамический расчет прогресса: "Вопрос X из Y", где Y — количество шагов, удовлетворяющих `showIf` в текущей ветке.
- Обеспечить автоматический переход к следующему вопросу при выборе в типах `single`.
- Добавить логику сбора ответов только из видимых (`visibleSteps`) шагов.

### Результаты квиза (`src/components/quiz/QuizResults.tsx`)
- Переписать `calculateResult` для точного соответствия новым правилам:
    - Ограничение до 3 релевантных услуг.
    - Приоритет массажа перед практиками.
    - Специальная пометка "Рекомендуем" для первой услуги.
    - Добавление кнопки "Обсудить с мастером" (ссылка на Telegram).
    - Вывод поясняющего текста для сценария "Первый визит" с акцентом на векторный массаж.

### Интеграция и защита (`src/lib/quiz.functions.ts`)
- Убедиться, что отправка лидов корректно обрабатывает новые динамические данные.

## Технические детали
- Использование ID опций для логики переходов вместо сравнения строк.
- Изоляция веток через фильтрацию массива `steps` в реальном времени.
- Включение honeypot и валидации на стороне сервера.
