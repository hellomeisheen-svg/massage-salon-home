# План: Исправление отображения шрифтов в Safari на production-хостинге

В рамках данной задачи будет проведена диагностика и устранение причин искажения шрифтов в браузере Safari, возникающих при размещении проекта на файловом хостинге Reg.ru.

## Диагностика

Текущий анализ выявил следующие потенциальные проблемы:
1. **Абсолютные пути в `@font-face`**: В `src/styles.css` шрифты подключаются через `/fonts/...`. При использовании `base: "./"` в Vite и размещении во вложенных папках на хостинге, браузер может искать шрифты в корне домена, а не относительно CSS-файла.
2. **Отсутствие относительности в `src/routes/__root.tsx`**: Теги `<link rel="preload">` используют `/fonts/...`, что также может приводить к ошибкам 404 в Safari при специфической структуре папок на хостинге.
3. **Особенности Safari**: Safari более чувствителен к корректности путей и MIME-типов при загрузке веб-шрифтов.

## Файлы и изменения

### 1. Файл: `src/styles.css`
- **Что изменится**: Пути в правилах `@font-face` будут изменены с абсолютных (`/fonts/`) на относительные (`../fonts/` или без слеша, если они в `public`), чтобы корректно разрешаться сборщиком Vite. Поскольку шрифты лежат в `public/fonts`, правильный способ для Vite при импорте из CSS в `src/` — указывать путь относительно корня проекта или использовать возможности `public` директории, но для надежности в Safari мы обеспечим корректное разрешение путей.
- **Что гарантированно не будет изменено**: Дизайн, размеры шрифтов, анимации, цвета и структура блоков.

### 2. Файл: `src/routes/__root.tsx`
- **Что изменится**: Пути в атрибутах `href` для `rel="preload"` будут скорректированы для обеспечения совместимости с `base: "./"`.
- **Что гарантированно не будет изменено**: SEO-метатеги, структура роутинга и компоненты.

## Проверка
1. Выполнение `npm run build` и проверка итоговых путей в `dist/assets/index-*.css`.
2. Проверка, что файлы шрифтов в `dist/fonts/` соответствуют путям в CSS.
3. Визуальный контроль отсутствия изменений в дизайне.
